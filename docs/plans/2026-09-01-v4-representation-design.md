# V4：候选表征增强 设计文档

> 2026-09-01 · 状态：待确认范围 · 依据：V3 PPO 破楼层未破通关墙 → 瓶颈指向候选表征

## 1. 背景与结论

REINFORCE / PPO / 大网络都试过，楼层到 33 层但通关率卡 2-3%。剩余变量只有"模型看到的信息"。
调研了绑定层现状（CardInstance 只暴露 id/cost_for_turn/type/upgraded/is_strike，Card 只暴露 id/rarity/type 等），确认：**卡牌效果数值、地图路径、事件语义三块都缺失**。

## 2. 三个特征组（按性价比排序）

### A. 地图路径前瞻（纯 Python，最高性价比）
- 现状：MAP_SCREEN 候选只有"目标房间类型"1 个维度，模型看不到"这个精英后面连着什么"
- 增强：对每个候选节点，沿地图向下看 6 层，统计可达的精英/篝火/商店/事件/宝箱/Boss 数量，编码成向量
- 依据：sts-rl-agent 的核心结论"这游戏软肋是选路"，前瞻信息直接喂给选路决策
- 成本：纯 Python，SpireMap 已暴露 get_room_type，零 C++ 改动

### B. 卡牌效果字典（手写 ironclad 卡牌数据表，中等成本高价值）
- 现状：卡牌特征 = 类型/稀有度/费用(恒0)/升级/名字哈希桶——模型不知道"重锤打 32、打击打 6"
- 增强：手写 ~75 张铁甲卡牌的效果字典（基础伤害/基础格挡/费用/是否能力牌/是否 AOE/是否抽牌/是否消耗/自身伤害/成长性标签），候选卡牌按名查表编码
- 成本：纯 Python dict，无 C++；缺点是要手写数据表（一次性）

### C. 卡牌费用接线（快速修复）
- 现状：candidate_encoder 里费用恒 0（早期"Card 无 cost 属性"的遗留），但 CardInstance.cost_for_turn 现在已暴露
- 增强：REWARDS 选牌屏的候选卡牌费用用 gc.get_card_reward()[idx].cost_for_turn 填真实值

## 3. 明确不做（YAGNI）

- 事件选项语义（sim 未暴露事件文本，硬抠工程量大、收益存疑）
- 卡牌伤害的 C++ 运行时计算（卡牌效果是代码非数据，动态受力量/易伤影响，运行时算不准——字典静态值够用）

## 4. 维度与模型改动

- 候选维度 368 → 预计 ~392（A 组 24 维 + B 组并入现有卡牌段的扩展）
- Scorer 输入维度相应调整 → 需重新训练（PPO，沿用 V3 的 (512,256) + ValueNet 框架）
- 候选编码函数、env、main.py 的 368 常量都要同步改

## 5. 验收标准

- 特征单测：地图前瞻对"直通 Boss"的路径给出更高 Boss 计数；卡牌字典对 Bash/重锤给出正确伤害
- 重训 PPO 5000 局，100 留出种子评估：目标通关率 > 3%（破 REINFORCE/PPO 的 2-3% 平台）
- 若通关率仍无提升，则结论锁定为"终端奖励 + 宏观决策粒度"是根因，转向奖励塑形或 LLM
