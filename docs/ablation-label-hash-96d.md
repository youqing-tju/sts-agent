# 候选向量 96 维 label 哈希消融报告

> 生成：2026-09-10 ｜ 权重：`checkpoints/ppo_v6_5000.pt`（obs 468 / cand 443 / hidden 512,256）
> 方法：**推理期遮蔽消融**（不训练、不改维度、不改任何已有模块）
> 脚本：`experiments/dim_ablation.py`（新建文件）｜ 原始数据：`logs/dim_ablation.json`

---

## 0. 问题

候选向量 443 维里，`[271, 367)` 是 **96 维 label 文本 crc32 哈希**（`candidate_encoder.py:266` `_encode_label`：
label 转小写 → 按 `[a-z0-9]+` 分词 → 每词 `crc32 % 96` → 置位）。

问题：**删掉这 96 维（443 → 347），模型会变差吗？**

---

## 1. Part 1：决策点前向消融（与样本功效无关的硬证据）

采集：20 局 RulePolicy（MCTS@200）× 1005 个决策点 / 3130 个候选。

### 1.1 冗余性实证：这 96 维 100% 由 bits 段决定

把每个候选的 bits 段 `[215,223)`（`idx1/255, idx2/255, idx3/255, reward_type/6, is_potion, is_potion_discard`）
当键分组，检查同组内的 label 段 `[271,367)` 是否唯一：

| 检验 | 结果 |
|---|---|
| 不同 bits 段取值数 | 28 |
| 其中 label 段**不唯一**的组数 | **0** |
| 反向：不同 label 段图案数 | **26**（28 个 bits 值 → 26 种图案） |
| **不同 bits 段共用同一 label 图案（真实碰撞）** | **2 处** |

**结论**：label 段是 bits 段的确定性函数，**独有信息量 = 0**；而 bits 段本来就在向量里。
且 28 → 26 的压缩意味着**实测存在 2 处碰撞**——不同动作在这 96 维里完全同形，模型无法区分。

### 1.2 影响范围：只在"模型本来就游移不定"时起作用

| 量 | 值 |
|---|---|
| V6 的 top1−top2 分差（中位数，四分位） | 6.851 ｜ [2.730, 6.851, 9.900] |
| 置零 96 维造成的 max 分扰动（中位数） | 1.441（≈ 典型分差的 21%） |

按分差分层的 argmax 翻转率：

| top1−top2 分差 | 翻转率 |
|---|---|
| 0 ~ 2.73 | **30.68%**（77/251） |
| 2.73 ~ 6.85 | 3.17%（8/252） |
| 6.85 ~ 9.90 | **0.00%**（0/450） |
| > 9.90 | **0.00%**（0/52） |

**模型有明确偏好时（分差 > 6.85，共 502 个决策点 = 50%），置零从不改变决策。**
全部 85 次翻转都挤在分差 < 6.85 区间——这 96 维的实际作用是"两个选项近乎打平时当个微弱 tie-breaker"。

### 1.3 正对照 C 的解读（重要纠正）

正对照 C = 置零卡牌 one-hot `[22,118)`（前 96 维）。其翻转率 6.37% **低于** B 的 8.46%，
但**不能**据此说"标签哈希比卡牌信息更重要"——因为：

- label 段对**每个候选**都非零（bucket 18 恒亮 + 1 个 bits 桶），B 的扰动作用于全部决策点；
- 卡牌 one-hot 只对"候选本身是卡"的决策点非零，**多数决策点是 no-op**（打分变化中位数 0.0）。

所以 **C 是一个弱对照**，两者的翻转率不可直接比较。

## 2. Part 2：博弈级配对对比

配置：3 条件 × **300 种子** × **MCTS@2000** × **10 worker**，同权重、同种子集；耗时 4.1 分钟。

| 条件 | 通关率 | 通关数/300 | 平均楼层 |
|---|---:|---:|---:|
| **A 基线**（不遮蔽） | 21.33% | 64 | 37.81 |
| **B 删 96 维 label 哈希** | **22.33%** | 67 | 37.88 |
| C 删卡牌 one-hot 前 96 维（正对照） | 23.67% | 71 | 37.36 |

| 对比 | 通关率差异 | z | p |
|---|---:|---:|---:|
| A vs B | **+1.00 pp（B 更好）** | −0.296 | **0.767** |
| A vs C | +2.34 pp（C 更好） | −0.684 | 0.494 |

**A vs B：无统计显著差异，且方向对"删除"有利**（B 通关率与平均楼层都略高）。

### ⚠️ 必须说明的灵敏度缺陷

**正对照 C 也没变差**。这意味着这个实验配置**测不出这类量级的破坏**——既可能真是"删了没事"，
也可能只是**功效不足**（300 种子下两比例差异的 SE ≈ 3.3pp），或 C 这个操作本身弱
（卡牌信息还有属性段 12 维 + 语义段 38 维兜底）。

**因此 A vs B 的"无差异"属弱证据。** 结论主要靠 §1 的演绎性证据（与样本量无关）支撑。

## 3. 结论与建议

| 证据 | 强度 | 方向 |
|---|---|---|
| 96 维由 bits 段 100% 决定（0/28 反例） | **强（演绎）** | 支持删 |
| 实测 2 处碰撞（不同动作同形） | **强** | 支持删 |
| 干扰量级仅为典型分差的 21%，且 50% 决策零影响 | **中** | 支持删 |
| 博弈级：删后通关率 +1.0pp，p=0.77 | **弱（功效不足）** | 支持删 |

**建议：删除这 96 维（443 → 347）。**

理由：核心证据是**演绎性**的——该段信息完全可由 bits 段推出，且实测存在碰撞歧义。
Part 2 至少没有反对证据（方向还有利）。保留它的唯一理由是"以防万一"，代价是 21.7% 的
零信息维度 + 碰撞歧义 + 每步 96 维的前向开销。

**保留的后悔成本 vs 删除的后悔成本**：若删后真变差，回滚只需恢复 96 维并重训；
若保留，则永久背着一个已被证明为零信息的段。

---

## 4. 局限

1. **推理期消融 ≠ 训练期删除**。本实验衡量的是"已训练模型（训练时含该段）对它的依赖"。
   若删掉并**重训**，模型可能改用 bits 段补偿，实际影响只会更小——所以本实验是**保守上界**。
2. Part 2 用 MCTS@2000（弱战斗）。已知低 search 预算会掩盖版本差异，
   故本实验对"宏观策略差异"的分辨力有限。
3. Part 2 只存了聚合结果，未存 per-seed 记录 → **无法做配对 McNemar 检验**（比两比例 z 更敏感）。
   若要强化，需给脚本加 per-seed 输出。
4. 决策点由 RulePolicy 生成（覆盖真实状态分布，但不是 V6 自身的状态分布）。
