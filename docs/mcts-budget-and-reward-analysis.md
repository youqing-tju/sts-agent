## 一、MCTS 需要多少预算才算"最优"

### 1.1 理论标度：需要多少仿真，由「噪声 / 分差」的平方决定

战斗搜索器（`BattleScumSearcher2`）在根节点要把 b 个可选动作排序。每个动作的价值估计
由若干次 rollout 平均得到，标准误 SE = σ/√(n_arm)，其中 σ 是单次 rollout 的终点价值标准差。

要把「最优动作」与「次优动作」区分开（真实分差 Δ），需要：

```
n_arm ≥ (z·σ/Δ)²        每次 visit 给一个 arm
N_total ≈ b · (z·σ/Δ)²   z≈2（约 95% 置信）
```

**核心结论：所需预算 ∝ b·σ²/Δ²。** 分差 Δ 缩小一半，预算要涨 4 倍。

### 1.2 铁甲战士的具体参数

| 量 | 铁甲的实际取值 | 说明 |
|---|---|---|
| **分支因子 b** | 早期 **5–6**；中期 7–10；多敌战 **10–15** | 能量 3 + 手牌 5 → 可出的牌 3–5 张，再乘目标数（单体/群体）× 药水 × END TURN。低费/0 费组件（Anger、Bloodletting、Seeing Red、Offering）会**加深回合内序列深度**，使有效树规模指数上升 |
| **rollout 噪声 σ** | **偏大**（估 15–25 HP 量级） | 三处放大：① 牌组 10→30+ 张，**抽牌顺序方差大**；② 敌人行动有 RNG；③ 铁甲大量**自伤/力量/消耗**卡使 HP 轨迹非单调 —— 是否早期抽到 Demon Form 直接改变整场战斗走向 |
| **价值分差 Δ** | 早期 **极小**，后期**极化** | 早期手牌常是 Strike/Defend 的近等价组合，真实 Δ 可能 <1 HP；而「能力牌 vs 节奏牌」的真实 Δ 很大，但 **rollout 在短视界内看不到**（见 1.4） |

### 1.3 预算 → 可分辨的最小分差（σ=20、b=10、z=2 代入）

| 目标分差 Δ | 所需总仿真 N |
|---|---|
| 10 HP | 160 |
| 5 HP | 640 |
| 2 HP | **4,000** |
| 1 HP | **16,000** |
| 0.5 HP | 64,000 |
| 0.2 HP | 400,000 |

**我们目前用在 @20000** → 每个 arm 约 2000 次 visit → SE ≈ 20/√2000 ≈ **0.45 HP**
→ 能稳定分辨 **≥0.9 HP** 的取舍，低于这个就基本在噪声里掷硬币。

### 1.4 但铁甲有比"预算不够"更严重的问题：评价函数看不远

搜索器的终端评价是 `evaluateEndState`（用战斗结束时的 HP 差）。铁甲的核心机制是
**长视界投资**：

- Demon Form / Inflame / Limit Break：收益在第 3–5 回合之后；
- Corruption + 消耗协同：收益要等牌组循环一轮；
- Barricade / Entrench：格挡跨回合累积。

这些牌在短视界 rollout 里表现为「花 2–3 费换来 0 收益」，于是 MCTS **系统性低估**它们。
这**不是加预算能修的**——加预算只降 SE，不改变偏差（bias）。

> **结论：预算能解决「接近平的取舍」（Δ 小），解决不了「评价函数看不远的取舍」（bias 大）。
> 后者要靠更好的评价函数（例如把力量层数/已打出能力牌数纳入终端评价），而不是更多仿真。**

### 1.5 实测：拟合「预算 → 通关率」曲线

用同权重、250 与 500 种子实测（`logs/mcts_ab_*.txt`），按 1/√N 标度拟合
`p(N) = p_max − A/√N`：

| 权重 | N=5000 | N=10000 | N=20000 | 拟合 p_max | 拟合 A | 最大残差 |
|---|---|---|---|---|---|---|
| **V7** | 28.40% | 31.20% | 34.00% | **39.4%** | 784 | 0.33pp |
| **V6** | 25.70% | — | 36.40% | **47.1%** | 1513 | 0（仅 2 点） |

V7 三点拟合残差全部 <0.4pp，说明 1/√N 标度成立（这是蒙特卡洛误差的指纹）。

**楼层**拟合：V7 `p_max=42.9, A=250`；V6 `p_max=44.7, A=354`。

### 1.6 「要到最优还需要多少」——直接给数

| 目标（距该权重渐近线） | V7 所需 N | V6 所需 N |
|---|---|---|
| 差 5pp 以内 | **24,600** | 91,600 |
| 差 2pp 以内 | **153,800** | 572,500 |
| 差 1pp 以内 | 615,000 | 2,290,000 |
| 差 0.5pp 以内 | 2,460,000 | 9,160,000 |

**当前 @20000 的位置**：距 V7 渐近线还差 **5.4pp**，距 V6 渐近线差 **10.7pp**。

### 1.7 建议

| 用途 | 建议预算 | 理由 |
|---|---|---|
| **训练侧** | **8000**（V9 已用） | 要吞吐量；拟合显示 @8000 已达 39.4−8.8≈30.6%（≈渐近线的 78%） |
| **评估侧** | **50000 起步，逐步上探** | 拟合预测 +1.9pp（@20000 → @50000）；比 @20000 只多 ~1.8% 的绝对通关率提升，需实测 wall-clock 换算 |
| **部署/真实游戏** | 不设上限（可以慢） | 真实游戏不在意耗时 |
| **不建议** | 盲目堆到 150k+ | 5.4pp 的差距里，**bias 那部分堆钱也修不动**（见 1.4），性价比低 |

**⚠️ 本节的局限**（必须一起看）：
1. 实测点只有 2–3 个，种子数 250–500 → 单点噪声约 ±2pp，`p_max` 的外推有 **±3~5pp** 不确定度；
2. 假设 1/√N 标度在整个区间成立（在 Monte Carlo 主导区成立，但树搜索的 UCB 结构在极小 N 时可能偏离）；
3. `p_max` 是**该权重宏观策略下**的天花板，不是游戏最优——换更好的宏观策略会整体抬高曲线。

### 1.8 一个可以直接量出「收敛点」的实验（建议做）

`pyd` 已暴露所需接口：`sts.Agent.pause_on_combat = True`（在战斗决策点暂停）、
`sts.BattleContext().init_from_gc(gc)`（取当前战斗态）、
`sts.BattleSearcher(bc, simulation_count=N).best_action`（跑 MCTS 并取最优动作）。

**做法**：跑约 25–40 个真实战斗状态（覆盖 Act1/2/3、单体/多敌），对每个状态用
N ∈ {500, 1000, 2000, 5000, 10000, 20000, 50000} 各跑一次，与 N=50000 的参考动作比对：

- **决策一致率 vs N** —— 一致率到 95%/99% 的那个 N，就是「战斗决策实际收敛点」；
- 同时记录**分支因子 b**（`BattleAction.is_valid` 计数）与**不同预算下的分歧动作类型**
  （是「Strike vs Defend」这种近等价分歧，还是「能力牌 vs 节奏牌」这种结构性分歧）。

这比拟合曲线更直接，也能一次性验证 1.4 的「低估能力牌」假说。
**注意**：`BattleSearcher` 只读 `best_action`，读不到内部方差，所以只能测「决策稳定性」，
测不出 σ/Δ 本身。

## 二、MCTS 与 RL 是互补的（用户判断的量化形式）

### 2.1 训练侧 MCTS 预算 = RL 奖励的信噪比

PPO 的回报是终局的 `G = final_floor + 50·win`（γ=1，整局共享同一标量）。
战斗失误会污染这个标量：**一个完美的宏观决策（选对了卡、选对了路）可能因为战斗打崩而拿到低 G**。

于是可以写成：

```
G_observed = G_true(s_macro) + ε_combat
Var(ε_combat) ∝ 战斗失误率 ∝ f(训练侧 MCTS 预算)
```

训练侧预算 2000 → 8000（V9 在做的改动），等于**给 RL 的奖励降噪**：
同样的宏观决策，回报更可复现，策略梯度方向更稳。

**这不是"顺便优化"，而可能是 V6→V7 那些表征改动全都无效的原因之一**——
如果奖励噪声本来就盖住了表征带来的细微差异，那么再怎么改表征都测不出收益。

### 2.2 「MCTS 没打好，RL 就更倾向于保守」——可测形式

这个直觉可以量化验证。`logging/run_logger.py` 已记录每个宏观决策
（floor / screen / 候选 label 列表 / 所选 label / hp），所以可以直接统计策略分布：

| 统计量 | 预期方向（若假说成立） |
|---|---|
| ELITE 节点选择率 | 训练 MCTS 预算低的权重 → **显著更低** |
| 休息点「锻造/升级」 vs 「睡觉回血」比例 | 低预算 → 更倾向回血（保守） |
| 平均金币存量 / 药水囤积 | 低预算 → 更高（不敢用） |
| 商店消费率 | 低预算 → 更低 |

**做法**：用 V6 权重（训练 @2000）与 V9 权重（训练 @8000）各跑 100 局并开 `log_dir`，
按上表统计，做两比例 z 检验。**这个对比的变量很干净：唯一的差别就是训练侧战斗预算。**

## 三、要不要用「卡牌强度 / 抓取优先级」优化奖励？

### 3.1 直接结论：**不要把卡牌强度写进奖励**，但**应该改进奖励的结构**

### 3.2 为什么不建议（三条，按严重程度排）

**① 会被刷（reward hacking），而且刷的方向恰好是错的。**
奖励「拿了高分卡」→ 最优策略变成「见高分卡就拿」→ 无视牌组协同。
而铁甲的抓取优先级**本质上是随牌组变化的**：

| 卡 | 在 A 牌组 | 在 B 牌组 |
|---|---|---|
| Barricade（壁垒） | 防战核心，T0 | 力量战里是 3 费白板 |
| Limit Break（极限爆发） | 有力量来源时终结技 | 无力量来源时是死牌 |
| Demon Form | 长局核心 | 快攻牌组里拖节奏 |
| Corruption | 消耗流发动机 | 无消耗牌时是诅咒 |

静态优先级表会给模型植入一个**系统性错误先验**。

**② 任何非势函数的中间奖励都会改变最优策略。**
Ng, Harada & Russell (1999) 的定理：只有**势函数形式**
`F(s, s') = γΦ(s') − Φ(s)` 才保证最优策略不变。把「卡牌强度」当成动作奖励，
等价于宣告「拿到强卡」本身就是目的——那不再是「爬塔通关」这个任务。

**③ 我们其实已经把这类知识放对了地方——特征，而不是奖励。**
`models/card_data.py` 的 42 个效果字段、38 维卡牌语义、35 维「卡 × 牌组」流派交叉项，
都在**候选向量**里，policy 可以直接用。这正是 V5/V6 的收益来源：

| 版本 | 做法 | 通关率 |
|---|---|---|
| V4 | 只有 16 字段粗语义 | 7.20% |
| V5 | 修 13 处数据错漏 + 42 字段 + 38 维语义 + 35 维交叉项 | 12.20% |
| V6 | 补 76 维 KB（药水/遗物/事件从无到有） | 25.70% |

**把启发式放进特征 → 模型自己学怎么用（含"这次该不该抓"）；放进奖励 → 模型学怎么刷它。**

### 3.3 那奖励该改什么？按性价比排序

| 优先级 | 改动 | 理由 | 风险 |
|---|---|---|---|
| **P0** | **训练侧 MCTS 2000 → 8000**（V9 已做） | 直接降 `Var(ε_combat)`，不改变最优策略 | 无（训练变慢） |
| **P1** | **修 credit assignment**：现在 γ=1、整局共享同一 G，一局 ~40 个决策拿到同一个标量，advantage 退化成「这局好不好」 | PPO 已有 ValueNet，但 γ=1 全共享使其几乎无用武之地。改用 **GAE(λ)** 或按 Act 分段回报，才能区分「哪一步决策错了」 | 中（需调 λ/归一化） |
| **P2** | **按 Act 分解奖励**：过 Act1/2/3 各 +b，通关再 +50 | 让梯度在早期就获得信号，缓解稀疏 | 低（b 要小，避免怂恿磨时间） |
| **P3** | **势函数塑形 PBRS**：`Φ(s) = w1·牌组质量 + w2·hp比例 + w3·(1−诅咒数/10)`，其中「牌组质量」用现有卡牌强度表 × 流派一致度算 | 理论上保最优策略，可白拿"游戏知识" | 低（但要先验证 `Φ` 的相关性） |
| **不建议** | 战斗 HP 损失作为密集奖励 | 会直接教模型「躲精英/躲战斗」，反而降低上限 | 高 |

### 3.4 建议的实验设计（paired A/B，统一 MCTS@20000 评估口径）

同一 seed 序列、同一训练预算，只改奖励：

| 组 | 奖励 |
|---|---|
| **A 现状** | `G = floor + 50·win`（γ=1 共享） |
| **B** | GAE(λ=0.95) 替代共享 G（只改 credit assignment，不改奖励值） |
| **C** | A + 过 Act 的小 bonus（Act1/2/3 各 +5） |
| **D** | A + PBRS Φ = 0.5·牌组质量 + 0.5·hp比例 |

判据：通关率 + 两比例 z 检验（≥500 种子）。

**为什么先做 B 而不是 C/D**：B 是**纯粹的估计量改善**（不动目标函数），
理论上没有副作用；C/D 会动目标函数，需要更多轮验证。而且如果 P1 的问题
（credit assignment 过粗）是主因，那么 C/D 的收益也会被它掩盖。
